# HomeFit

An offline home-workout and fitness-guide app built with Flutter. Everything
runs on the device: there is no account, backend, analytics, advertising or
network access in release builds. Personal data lives only in local storage
and leaves the device only when the user exports a backup file.

**Status:** feature-complete in code and covered by automated tests, but not
yet tested on a physical device or emulator, and not ready for store release.
See [docs/RELEASE_BLOCKERS.md](docs/RELEASE_BLOCKERS.md).

## Features

- **Onboarding** (skippable): name, level, goal, workout length, preferred
  days, equipment, impact preference and units. Every answer is optional and
  can be changed later.
- **Home**: today's plan day or a suggested workout, real weekly stats,
  streaks, quick actions and suggestions. No placeholder numbers: empty
  states are shown until there is history.
- **Workouts**: 32 ready-made workouts, an 88-exercise library with
  animated demonstrations, search, filters, sorting, favorites and a custom
  workout builder.
- **Guided player**: preparation, work, rest and side-switch phases, rep
  confirmation, pause/resume, skip exercise or rest, extra rest time, sound and haptic cues,
  keep-screen-on, automatic pause when the app goes to the background, and
  crash recovery from a saved checkpoint. Partial workouts can be saved.
- **Plans**: four 28-day plans with a fixed day-by-day schedule, start-date
  choice, missed-day handling, rescheduling, skip, pause/resume, leave and
  restart.
- **Progress**: activity chart, calendar, history with filters, session
  details, streaks and body measurements (metric or imperial; stored in
  canonical metric units).
- **Guide**: 22 articles and 20 tips with search, categories, bookmarks and
  reading progress.
- **Settings**: profile and preferences, workout cues, local reminders,
  theme, backup export/import with undo, reset progress, delete all data,
  privacy notice, health disclaimer, about and credits.

## Requirements

- Flutter 3.44.1 (Dart 3.12.1) – the version this was built and tested with.
  Dart 3.12 language features (null-aware elements, private named
  parameters) are used, so older SDKs will not compile it.
- Android: built with the Android SDK 36 toolchain. `minSdk`/`targetSdk`
  follow the Flutter defaults.
- iOS: the code has no iOS-specific blockers known, but it has not been
  built for iOS (no macOS machine was available).

## Running

```sh
flutter pub get
flutter run            # on a connected device or emulator
flutter test           # unit and widget tests
flutter analyze
```

No code generation is needed: models are serialized by hand and stored as
JSON documents, so there is no `build_runner` step.

The on-device smoke test needs a device or emulator:

```sh
flutter test integration_test/app_smoke_test.dart -d <device-id>
```

### Optional visual tools

Two tests render PNG files for visual review and are skipped by default:

```sh
# Contact sheets of every exercise figure
FIGURE_OUT=/tmp/figures flutter test test/tools/figure_render_test.dart
# Screenshots of key screens with real fonts
SCREENSHOT_OUT=/tmp/shots FLUTTER_ROOT=<flutter sdk> flutter test test/tools/screenshot_test.dart
```

## Adding content

All content is bundled JSON under `assets/data/`. Each file has the shape
`{"contentVersion": 1, "items": [...]}`. IDs are lowercase `snake_case`, are
permanent once shipped (history, favorites and plans refer to them) and
must be unique within their type.

After any content change, run `flutter test test/data/catalog_content_test.dart`.
It runs `CatalogValidator` over the bundled files and fails with a list of
every problem. Debug builds run the same validator at startup and log
problems to the console.

### Exercise

Add an object to the matching file in `assets/data/exercises/` (by
category). Required fields: `id`, `name`, `description`, `category`,
`difficulty`, `primaryMuscles`, `secondaryMuscles`, `equipment` (empty list
for bodyweight), `matRecommended`, `lowImpact`, `execution` (`timed` or
`reps`) with `defaultDurationSeconds` or `defaultReps`, `perSide`, `setup`,
`steps` (at least 2), `breathing`, `mistakes`, `easier`, `harder`,
`cautions`, `mediaPath` and `tags`. Copy an existing entry as a template.

`mediaPath` is either `figure://<id>` (procedural figure animation; add a
sequence in `lib/features/exercise_media/figure_library.dart`) or a bundled
asset path. A real image or video needs an `attribution` entry and an
update to [docs/ASSETS.md](docs/ASSETS.md); do not add media whose license
you cannot document.

### Workout

Add to `assets/data/workouts.json`: `id`, `title`, `description`,
`category`, `goal`, `difficulty`, `rounds`, `roundRestSeconds`, `tags` and
`steps`. Each step has a stable `id`, an `exerciseId`, a `type`
(`warmup`, `main` or `cooldown`), either `durationSeconds` or `reps`,
`restSeconds`, and optional `perSide`. Durations are estimated
automatically; do not add a duration field.

### Plan

Add to `assets/data/plans.json`. A plan has exactly 28 `days`, numbered
1–28 in `day`; each has a `type` (`workout`, `recovery` or `rest`), a
`workoutId` for workout and recovery days, and an optional `note`. Every
week needs at least one rest day. Enrolling copies the schedule into the
user's enrollment as assignments with their own IDs, so editing a shipped
plan does not change existing enrollments; it only affects new ones.

### Article

Add to a category file in `assets/data/articles/`. Articles need at least
250 words across `sections`, a `summary`, `tags`, and
`reviewStatus: "unreviewed"` until a qualified person has reviewed them.
`references` list only real publications (title, publisher, year) that
were actually used; never add a reference that was not consulted. See
[docs/CONTENT.md](docs/CONTENT.md).

## Backups

Settings → Backup & restore exports all personal data to a JSON file chosen
with the system file picker. Import validates the file (format, version,
size limit 10 MB, every record) before anything changes, replaces the data
all-or-nothing, and keeps the previous data so the import can be undone.
The backup format is documented in [docs/DATABASE.md](docs/DATABASE.md).

## Platform limitations

- Reminders are inexact (the app does not request exact-alarm permission),
  so they can arrive a few minutes late. Some Android manufacturers stop
  scheduled notifications for apps that are rarely opened.
- Notification permission is requested only when reminders are switched
  on. If it is denied, the app explains how to enable it in system
  settings; nothing else is affected.
- Android auto-backup is disabled (`android:allowBackup="false"`), so
  personal data is not copied to Google Drive. Users should export a backup
  file before changing devices.
- The app is locked to portrait orientation.
